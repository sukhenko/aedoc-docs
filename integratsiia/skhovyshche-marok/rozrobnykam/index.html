    Для розробників: API «Сховище марок» для ПРРО і РРО¶

    Сервіс зберігає актуальні статуси акцизних марок з облікової системи (BAS з підсистемою AEDOC) і відповідає касі по HTTP. Каса перевіряє марку перед продажем і повідомляє про продаж; облікова система забирає продажі сама. Каса працює лише з трьома методами, описаними нижче.

    Підключення¶

    Параметр Значення
    Базова адреса http://<сервер>:8766/ — комп'ютер, де встановлено службу AEDocSignService. Порт задає адміністратор (CashListenPrefix).
    Автентифікація Заголовок X-Auth-Token: <токен> у кожному запиті. Токен видає адміністратор служби.
    Формат JSON, кодування UTF-8. Запити з тілом — Content-Type: application/json.
    Дата і час Рядок yyyy-MM-ddTHH:mm:ss, місцевий час сервера, без часового поясу.
    Ідентифікатор марки uniqueIdentifier — код марки, зчитаний сканером. Регістр літер має значення. У шляху URL кодуйте його (percent-encoding).
    Рекомендований тайм-аут 2–3 секунди. Сервіс відповідає з власної бази, без звернень до облікової системи чи еАкциз.

    Сценарій роботи каси¶

    1. Сканування. Касир сканує марку. Каса викликає GET /marks/{id} або, для кількох марок у чеку, POST /marks/batch.
    2. Рішення. Каса вирішує, чи дозволити продаж: за статусом, ознакою sold, торговим об'єктом і ознакою stale.
    3. Фіскалізація. Каса пробиває чек ПРРО / РРО з марками як звичайно.
    4. Факт продажу. Для кожної марки чека — POST /marks/{id}/sold з номером чека. Відповідь 409 означає, що марку вже продано.

    Методи API¶

    GET /marks/{uniqueIdentifier}¶

    Стан однієї марки. Марки немає в сховищі — 404.

    GET /marks/T25I9MLQ0JEOYJ06z9v8W HTTP/1.1
Host: shop-server:8766
X-Auth-Token: ********

    Відповідь 200:

    {
  "uniqueIdentifier": "T25I9MLQ0JEOYJ06z9v8W",
  "found": true,
  "status": "НаСкладі",
  "eoObjectCode": "123456",
  "stampId": "4815162342",
  "updatedAt": "2026-10-07T14:21:05",
  "sold": false,
  "soldAt": null,
  "stale": false,
  "frozen": false,
  "source": "mirror"
}

    POST /marks/batch¶

    Стан кількох марок одним запитом — зручно для чека з багатьма позиціями. До 500 ідентифікаторів. Порядок відповіді збігається з порядком запиту. Марка, якої немає, повертається з "found": false.

    { "ids": ["T25I9MLQ0JEOYJ06z9v8W", "A11B22C33D44E55F66G77"] }

    Відповідь 200:

    {
  "items": [
    { "uniqueIdentifier": "T25I9MLQ0JEOYJ06z9v8W", "found": true, "status": "НаСкладі", "sold": false },
    { "uniqueIdentifier": "A11B22C33D44E55F66G77", "found": false }
  ],
  "stale": false,
  "frozen": false
}

    (Знайдені марки містять усі поля, як у GET /marks/{id}.)

    POST /marks/{uniqueIdentifier}/sold¶

    Фіксує продаж марки. Сервіс одразу позначає марку проданою і ставить факт у чергу для облікової системи. Повторний виклик для тієї самої марки повертає 409 — це захист від подвійного продажу. Викликайте після успішної фіскалізації чека.

    {
  "cashRegister": "Каса 1",
  "receiptRef": "4000123456",
  "soldAt": "2026-10-07T14:25:40"
}
    Поле Передавати Опис
    cashRegister рекомендовано Назва або фіскальний номер каси, до 100 символів.
    receiptRef рекомендовано Фіскальний номер чека. Потрапляє в облікову систему, яка зберігає перші 15 символів.
    soldAt ні Час продажу. Не передано — час сервера.

    Відповідь 200:

    { "status": "ПогашеноЕМ", "soldAt": "2026-10-07T14:25:40" }

    Відповідь 409 — марку вже продано:

    { "error": "already_sold", "soldAt": "2026-10-07T14:25:40", "receiptRef": "4000123456" }

    Поля відповіді¶

    Поле Тип Опис
    uniqueIdentifier рядок Код марки, як у запиті.
    found булеве false — марки немає в сховищі (лише в /marks/batch).
    status рядок Статус марки в обліковій системі — див. Статуси марок.
    eoObjectCode рядок Код торгового об'єкта еАкциз, де зараз марка. Порожньо — не визначено.
    stampId рядок Ідентифікатор марки в еАкциз.
    updatedAt дата-час Коли запис марки востаннє змінився в сховищі.
    sold, soldAt булеве, дата-час Марку продано через сервіс і час продажу.
    stale булеве true — облікова система давно (за замовчуванням понад 15 хв) не підтверджувала актуальність даних. Статус може бути застарілим.
    frozen булеве true — сховище тимчасово заморожене (перехід на сховище або відкат). Продажі не приймаються.

    Рекомендоване правило продажу. Дозволяти продаж, якщо status = "НаСкладі", sold = false і eoObjectCode збігається з кодом торгового об'єкта цієї каси. При stale = true — діяти за політикою магазину: попередити касира або заборонити продаж. Остаточне рішення завжди за касовим ПЗ.

    Статуси марок¶

    Поле status містить системне ім'я значення. Порожній рядок — статус не встановлено.

    Значення status Що означає
    НаСкладі Марка на складі торгового об'єкта.
    ПогашеноЕМ Марку продано (погашено).
    Вдорозі Марка в дорозі за вхідним документом.
    ВдорозіПереміщення Марка в дорозі між власними об'єктами.
    ВдорозіКонтрагенту Марка в дорозі до покупця.
    ВідвантаженоКонтрагенту Марку передано покупцю.
    МиВідхилено Ми відхилили вхідний документ з маркою.
    ОтримувачВідхилено Отримувач відхилив наш документ з маркою.
    НеАктивована, Активована, Розмитнена Етапи життя марки імпортера (до надходження в продаж).

    Коди відповідей¶

    Помилки повертаються у форматі { "error": "<код>", "message": "<опис>" }.

    HTTP error Коли Що робити касі
    200 — Успіх. —
    400 bad_request Неправильне тіло запиту, понад 500 id, хибний формат soldAt. Виправити запит.
    401 unauthorized Немає токена або він хибний. Перевірити налаштування каси.
    404 not_found Марки немає в сховищі. Не продавати; звернутися до відповідального за облік.
    409 already_sold Марку вже продано (повертаються soldAt і receiptRef першого продажу). Не продавати повторно.
    503 frozen Сховище заморожене на час переходу або відкату. Продаж через сервіс неможливий; діяти за резервною політикою магазину.
    503 storage_not_ready, auth_not_configured Сховище ще не запущене або в службі не задано токен. Повторити пізніше; повідомити адміністратора.
    500 storage_error Внутрішня помилка служби. Повторити запит; при повторенні — до адміністратора.

    Повторний запит після обриву зв'язку. Якщо відповідь на /sold не надійшла, повторіть запит. Відповідь 409 з тим самим receiptRef означає, що перший запит уже зафіксував продаж.

    Приклади¶

    curl:

    curl -H "X-Auth-Token: $TOKEN" http://shop-server:8766/marks/T25I9MLQ0JEOYJ06z9v8W

curl -X POST -H "X-Auth-Token: $TOKEN" -H "Content-Type: application/json" \
  -d '{"cashRegister":"Каса 1","receiptRef":"4000123456"}' \
  http://shop-server:8766/marks/T25I9MLQ0JEOYJ06z9v8W/sold

    PowerShell:

    $h = @{ "X-Auth-Token" = "********" }
Invoke-RestMethod "http://shop-server:8766/marks/T25I9MLQ0JEOYJ06z9v8W" -Headers $h

Invoke-RestMethod -Method Post "http://shop-server:8766/marks/batch" -Headers $h `
  -ContentType "application/json; charset=utf-8" `
  -Body '{"ids":["T25I9MLQ0JEOYJ06z9v8W","A11B22C33D44E55F66G77"]}'

    Налаштування служби (для адміністратора)¶

    Сховище — частина Windows-служби AEDocSignService. Налаштування — у файлі AEDocSignService.ini поруч зі службою, секція [Storage]. Після зміни перезапустіть службу.

    AuthToken = <токен для каси>

[Storage]
Enabled          = 1
ConnectionString = Server=.\SQLEXPRESS;Database=AEDocStorage;Integrated Security=true
CashListenPrefix = http://+:8766/
StaleMinutes     = 15
    Параметр Опис
    AuthToken Токен доступу. Той самий токен указується в обліковій системі і в налаштуваннях каси. Порожній — каса отримує 503.
    Enabled 1 — сховище увімкнене.
    ConnectionString Підключення до MS SQL. Базу і таблиці служба створює сама, якщо має права.
    CashListenPrefix Адреса, на якій служба приймає запити кас. Порожньо — API для кас вимкнено.
    StaleMinutes Через скільки хвилин без сигналу від облікової системи відповіді отримують stale = true.

    Щоб каси з мережі могли звертатися до служби, один раз виконайте від імені адміністратора:

    netsh http add urlacl url=http://+:8766/ user="NT AUTHORITY\SYSTEM"
netsh advfirewall firewall add rule name="AEDOC Storage 8766" dir=in action=allow protocol=TCP localport=8766

    Стан сховища можна перевірити на самому сервері: http://localhost:8765/storage/health — версія схеми, кількість марок, не забрані обліковою системою продажі, ознака заморожування.
