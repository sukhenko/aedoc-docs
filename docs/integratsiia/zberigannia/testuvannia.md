# Емуляція навантаження 1000 документів АЕД, з загальною кількістю 1 млн марок

<span class="badge badge--done">Тестування</span>

Щоб отримати об'єктивну картину того, як поводиться база даних при роботі з підсистемою еАкциз у стандартній конфігурації — без винесення даних у зовнішнє сховище — було проведено окреме контрольне тестування.

## Умови проведення тесту

Тестування виконувалось на серверній версії платформи **BAS** з використанням **MS SQL Server** у якості СУБД. Конфігурація — самостійна (standalone) конфігурація **AEDOC**, без сторонніх залежностей і розширень.

Для тесту було створено **1000 документів АЕД** (акцизних електронних документів), кожен з яких містив **1000 акцизних марок**, що належать одиниці групування ідентифікації (УГІ). Таким чином, фактично було протестовано процес обробки та завантаження **одного мільйона акцизних марок** — обсяг, наближений до реальних умов експлуатації.

Ці результати дають чітке уявлення про те, наскільки зростає база даних при активній інтеграції конфігурації з державною системою еАкциз, і дозволяють заздалегідь спланувати необхідні ресурси для стабільної роботи системи.

## Практичний висновок для торгових підприємств

Для невеликої мережі магазинів або поодиноких торгових точок, які прагнуть автоматизувати облік акцизних марок з повноцінною інтеграцією до системи еАкциз, отримані показники росту бази є цілком обґрунтованими та некритичними.

<div class="callout">
Наприклад, при середньому обсязі продажу акцизних марок на рівні <strong>близько 300 позицій на день</strong>, орієнтовний річний приріст бази даних складе приблизно <strong>1,4 ГБ на рік</strong> — показник, який не створює жодних практичних обмежень для стабільної роботи облікової системи навіть на стандартному обладнанні.
</div>

## Плани на майбутні релізи

Розробка підсистеми еАкциз триває, і в найближчих оновленнях передбачено впровадження механізму стиснення даних для вже погашених (використаних) акцизних марок. Це дозволить додатково скоротити обсяг бази даних без втрати доступності історичних даних для звітності та аналізу.

<p class="note-small">* Наведені показники отримані на тестовому середовищі та можуть відрізнятись залежно від структури документів, кількості одночасних інтеграцій та налаштувань конкретної інформаційної бази.</p>
